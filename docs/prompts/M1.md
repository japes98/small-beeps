## 1. Scope

Bring the chip from reset to a known, timed, interrupt-driven state, using only what docs/HARDWARE-SPEC.md, the vendored SDK headers and the allowed FM-1-RE documents say:
- **Clocks:** set the system clocks the firmware will run at, as the spec allows, and verify them by black-box measurement in fwtest.
- **Interrupts:** our own vector table and handler entry/exit, with nesting and priorities only as far as M1 needs; a fault or unexpected interrupt is reported over the debug channel and halts cleanly, so tests can detect it.
- **Timer:** a periodic timer interrupt as the system tick. The heartbeat moves from polling to the tick, and the main loop idles in the low-power wait between ticks.
- **Core 1:** only if the spec makes it necessary for M1; otherwise leave it parked and say so in the design notes.

Where the spec gives requirements, meet them with your own design. Where it is silent or a fact is emulator-only, either confirm it with your own black-box test or file a spec request in docs/SPEC-REQUESTS.md (by PR) and tell the owner. Never look anywhere else.

## 2. Tests
