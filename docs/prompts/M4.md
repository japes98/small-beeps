## 1. Scope

Get sound out, from HARDWARE-SPEC.md, the SDK headers and the allowed FM-1-RE documents:
- **The output path:** the audio output as the spec describes it (format, rate, how samples reach it), double-buffered so the CPU fills one half while the other plays, driven by its interrupt. State the sample rate, block size and resulting latency, and why you chose them.
- **The audio API:** one block callback that engines implement (fill N stereo or mono samples, as the hardware takes them), plus how an engine reads the input events from M3 between blocks. Later milestones and other people's engines build on this, so keep it small, documented and stable, alongside the input API.
- **A test instrument:** proves the path end to end, not a synth design. For example, a few sine voices started and stopped by the keys with a simple click-free envelope, pitch from the key, volume from MASTER, plus a fixed test tone mode.
- **Underruns:** detect them, count them, report them over the debug channel; never glitch silently.
- **Cores:** keep core 1 parked unless the spec makes it necessary; M5 decides how to split voices.
