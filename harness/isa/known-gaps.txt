# The instruction forms the pinned toolchain knows for the firmware's CPU
# flags (-mcpu=r3 -mfprev1) that fwtest does not run, each with the reason
# (C-HARNESS-ISA, harness/isa/isa_check.py; docs/HARNESS.md,
# "Instructions"). One shape per line (isa_check.py's shape(): the vendor
# disassembly, registers R, pairs RR, numbers #, halves .H, register lists
# by what they hold), a tab, a reason. The check fails on a form that does
# not run and has no line here, on a line no such form has any more, and on
# a line that is also the shape of a form that runs. Written by session
# spec-isa-audit (2026-10-28) from the check's own output; remove a line
# when its forms run.
#
# reason simd: a SIMD or DSP form only hand-written assembly reaches (the
#   compiler emits none of them and has no builtin for them): not
#   implemented until a firmware needs one (the owner, 2026-10-28)
# reason operation-open: `><` (with or without (sat)), `<c>` (also
#   __builtin_pi32v2_rotrc) and copex: the toolchain shows no result for
#   them (HARDWARE-SPEC Q-32)
# reason push-clear: the pushes marked (c), whose clearing the toolchain
#   does not show (Q-34)
# reason trap: `bkpt` (the compiler's __builtin_trap) ends the run as a
#   trap, by design (the owner, 2026-10-28; fwtest decode says `trap`)
# reason system: privileged and system instructions (returns from
#   exceptions, events, breakpoints, software interrupts, secure-state
#   jumps, trigger): what they do is the chip's (Q-34)
# reason registers-not-modelled: moves, pushes and pops of pc, cnum, uspn,
#   icfgn and icfgs, which fwtest does not model (Q-34)
